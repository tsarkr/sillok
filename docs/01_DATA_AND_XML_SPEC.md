## 1.2 XML 계층 구조 및 날짜 상속 메커니즘

`history.dtd` 기반 실록 XML은 `level1`부터 `level6`까지의 재귀적 계층으로 구성된다.

```text
level1 / level2 (권·연도 단위, biblioData[@type="L"])
  └── <date><dateOccured type="재위연도|간지|서기|중국연호">...</date>
        └── level3 (월 단위 또는 총서/부록 기사)
              └── level4 (일 단위, biblioData[@type="L"])
                    └── <date><dateOccured type="서기|간지|재위연도">...</date>
                          └── level5 / level6 (개별 기사, biblioData[@type="T"])
                                ├── <title><mainTitle>한글 기사 제목</mainTitle></title>
                                ├── <subjectClass>주제 분류</subjectClass>
                                └── <text><content><paragraph>한문 원문 + <index> + <annotation> + <postScript></paragraph>
```

### 실측으로 확인된 계층 분포 및 상속 필요성
전체 673개 XML 전수 스캔 결과, 개별 기사를 뜻하는 `biblioData[@type="T"]` 노드는 `level5`에만 존재하는 것이 아니라 전 계층에 걸쳐 분포함이 확인되었다:
- `level2`: `26`건 / `level3`: `289`건 / `level4`: `277`건 / `level5`: `377,790`건(서로게이트 에러 5파일 제외 기준) / `level6`: `152`건
- 또한 기사 노드의 `biblioData[@type="T"]/date`에는 `<dateOccured type="서기">`만 기록되어 있고, **`간지`(예: `丙申`)와 `재위연도`(예: `태조 1년 7월 17일`)는 상위 `level2`~`level4`의 `biblioData[@type="L"]/date`에만 기록**되어 있다.
- 이에 따라 [src/sillok/data/xml_parser.py](file:///home/nsua/Dev/sillok/src/sillok/data/xml_parser.py)의 `_walk(node, parent_date_ctx)`는 트리 하강 시 상위 노드의 `date_iso`, `date_ganji`, `date_reign`, `date_china`를 하위 노드로 상속·병합한다. 그 결과 전수 추출된 `381,701`건 중 총서/부록 등을 제외한 **`380,010`건(`99.56%`)**이 완전한 서기·간지·재위연도 3종 날짜를 보유하게 되었다.

## 1.3 전수 파싱 과정에서 발견된 4가지 결함·특이사항 및 해법

### 1) 5개 XML 파일의 UTF-16 서로게이트 쌍 NCR 파싱 오류 및 복구
표준 `xml.etree.ElementTree.parse()`로 673개 파일을 일괄 검사한 결과, 다음 5개 파일(`3,167`건의 기사 포함)에서 `ParseError: reference to invalid character number` 예외가 발생하였다:
- `data/2nd_wqa_106.xml` (471건)
- `data/2nd_wra_104.xml` (567건)
- `data/2nd_wra_105.xml` (708건)
- `data/2nd_wrb_104.xml` (665건)
- `data/2nd_wrb_105.xml` (756건)

**원인 분석**: 해당 위치(예: `2nd_wqa_106.xml` 2781행)에는 CJK Extension B 영역의 한자 `𥘼` (`U+2563C`)가 단일 코드포인트가 아닌 **UTF-16 서로게이트 쌍 숫자 문자 참조(`李&#55381;&#56892;`)**로 기록되어 있었다. XML 1.0 명세는 `0xD800`~`0xDFFF` 서로게이트 코드포인트의 숫자 문자 참조를 금지하므로 Expat 파서가 예외를 발생시킨다.

**해법 (`sanitize_xml_surrogates`)**:
파싱 직전 정규식 `_SURROGATE_NCR_RE`로 연속된 상위 서로게이트(`0xD800`–`0xDBFF`)와 하위 서로게이트(`0xDC00`–`0xDFFF`) NCR 쌍(10진수/16진수 모두 지원)을 탐지하여 실제 보조 평면 유니코드 문자로 디코딩한다:

$$\text{codepoint} = \text{0x10000} + ((\text{hi} - \text{0xD800}) \ll 10) + (\text{lo} - \text{0xDC00})$$

이로써 `&#55381;&#56892;`는 손실 없이 정확한 한자 `𥘼`로 복원되며, 673개 XML 파일 **100% 무오류 파싱**을 달성하였다 (`378,534 + 3,167 = 381,701`건).

### 2) XML Pretty-Print 줄바꿈 공백 정규화
원천 XML은 인접한 `<index>` 태그 사이에 가독성용 개행 및 들여쓰기 공백을 삽입한다:
```xml
<index type="이름">慶侍中</index>
              <index type="이름">復興</index>
```
단순 `"".join(elem.itertext())`를 사용할 경우 `"慶侍中\n              復興"`처럼 한자 인명·관직이 분절된다. 파서의 `_normalize_text()`는 `_INDENT_NEWLINE_RE = r"[ \t\r]*\n[ \t\r]*"`를 빈 문자열로 축약하고 연속 수평 공백만 단일 공백으로 정규화하여 `"慶侍中復興"`으로 복원한다.

### 3) 주석(`annotation` 5종)과 `child.tail` 손실 방지
실록 XML 내 `<annotation>`은 `원주`(39,068건), `교감주`(27,812건), `악보`(904건), `소자쌍행`(228건), `번역주`(120건) 5종이 존재한다.
- 기본 설정(`include_annotations=True`, `include_collation_notes=False`)에서는 본문 의미를 보충하는 `원주` 등은 유지하고, 판본 대조 기호인 `교감주`(예: `奉國(寶)〔璽〕詣太祖邸`의 `〔璽〕`)는 제거하여 `奉國(寶)詣太祖邸` 형태로 깔끔히 정제한다.
- `_iter_clean_text()`는 `<annotation>` 노드를 건너뛸 때도 부모 루프에서 `child.tail`을 반드시 이어서 수집하므로 후속 한자가 누락되지 않는다.

### 4) 사론(`<postScript type="史論">`) 분리 추출
사관의 논평인 `<postScript>`는 본문 서술과 문체 및 기능(`【史臣...曰: ...】`)이 다르므로, 본문(`body_hanja`) 추출 시 제외하고 별도의 `postscripts` 필드에 수집한 뒤 학습 포맷터에서 `<|postscript|>` 제어 토큰으로 명시적으로 구분한다.
